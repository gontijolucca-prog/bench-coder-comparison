Aider 0.86.2 partial
Partial output — no build.

Aider created base files (package.json, vite.config.ts, tsconfig.json, App.tsx) but the MiniMax-M3 model failed to conform to Aider's whole-file edit format. Files with corrupted names were created (literal }, ), </html> as filenames). Missing: index.html, main.tsx, index.css, tailwind.config.js.

Root cause: MiniMax-M3 doesn't follow Aider's strict file-editing format (path on first line, content between markers). The model mixes content with format markers. Aider's --edit-format whole didn't help — the model still produced malformed output after 3 reflections.

Verdict: Aider + MiniMax-M3 is not a viable combination for multi-file project creation.
Kilo Code 7.4.7 no output
No files created.

Root cause identified: The kilo run command in headless mode loads zero tools ("Available tools: ."). The model receives no file/bash/write tools, so it cannot create files. Tested with:
— minimax/MiniMax-M3 via MiniMax API: model emits tool-call JSON as text, CLI doesn't execute
— ollama-cloud/minimax-m3: same — Ollama Cloud doesn't support function calling
— ollama-cloud/kimi-k2.7-code: same — "Available tools: ." (empty)
— --pure: disables all tools
— --auto, --dangerously-skip-permissions: no effect
— --agent ask: agent loads but tools still empty

Diagnosis: kilo run (non-interactive mode) has a bug where it doesn't register tools with the model. The TUI mode works (tools load in interactive sessions), but headless/pipeline mode is broken in v7.4.7.
Gemini CLI 0.50.0 incompatible
Cannot use with MiniMax-M3.

Gemini CLI only supports Google Gemini models (requires GEMINI_API_KEY or Google auth). No support for custom OpenAI-compatible or Anthropic-compatible endpoints. Cannot participate in a fair same-model benchmark.

Installed and tested but excluded from comparison.
